## 📚 附录 · 深度解读

### 1. OpenAI 宣称攻克千禧年大奖难题「纳维-斯托克斯」

> 来源：[OpenAI 官方](https://openai.com/index/navier-stokes-solution/) · [Nature](https://www.nature.com/articles/d41586-026-02842-5) · [Quanta](https://www.quantamagazine.org/ai-has-solved-one-of-maths-1-million-millennium-prize-problems-20260908/) · [Science](https://www.science.org/content/article/how-ai-math-breakthrough-ignited-controversy) · [The Verge](https://www.theverge.com/ai-artificial-intelligence/993263/where-does-openai-get-mathematics-training-data) · 重要度 10/10

- **事件背景**：OpenAI 于 9/8 发布文章，宣称其内部模型生成了纳维-斯托克斯方程存在性与光滑性问题（克雷研究所七个千禧年大奖难题之一，奖金 100 万美元）的一个解：构造出三维流体中一个越转越细、越转越快、速度趋于无穷的涡旋，即光滑解会在有限时间内「爆破」，而能量始终有界。据报道，这项工作动用多达约 1 万个 AI agent 并行、历时约 88 小时，成本约为 OpenAI 此前数学实验的千倍、达「数百万美元」量级（首席研究官 Mark Chen 语）；OpenAI 称已于 9/6 完成 Lean 形式化验证。另有报道提到其构造包含外力项。
- **争议**：据 Fortune、Science 等报道，NYU 数学教授 Tristan Buckmaster 与 Levent Alpöge 此前已借助 AI 工具在相关问题上取得重要进展；OpenAI 称其工作始于 9/1、起因是听闻与二人相关的传闻，并表示并未有意利用二人的最新成果，Buckmaster 对此提出质疑。数学家 Andreas Thom 也指称 OpenAI 使用了其未发表的研究。The Verge 报道，部分数学家要求 OpenAI 说明其数学训练数据的来源。
- **产业影响**：若结论成立，这是 AI 首次攻克千禧年难题级别的问题。但对产业更重要的是方法本身——「上万 agent 并行 + 形式化验证 + 百万美元级算力」把前沿研究变成了可以按预算投入的工程问题。与此同时，「谁先做出来、用了谁的成果」的争议，暴露了 AI 科研在署名与数据来源上的规范空白。需要注意：按克雷研究所规则，奖项认定要求成果在权威期刊发表、发表后满两年并获学界普遍接受，目前距离这一步还很远。
- **竞品对位**：Google DeepMind 等机构同样在形式化数学方向投入；学界「研究者 + AI 工具」的协作路线与 OpenAI「集中算力 + 大规模 agent」的路线在本事件中形成直接对照。
- **PM 视角启示**：对产品而言，可迁移的是「并行生成 + 自动验证」这套范式——凡是结论能被机器验证的领域（代码正确性、规则一致性、配置校验），都可以用「多路生成、自动筛选」换取可靠性。另一面，AI 参与的产出越重要，越需要说清楚「依据了哪些资料」。
- **机会信号**：形式化验证工具链、大规模 agent 编排与成本控制、成果溯源与署名管理，都会被这类事件推高需求。
- **建议行动**：
  - 盘点产品中「结论可被机器验证」的环节，评估引入「并行生成 + 自动验证」的可行性与成本。
  - 为 AI 参与生成的重要内容建立来源记录（参考了哪些资料、哪些由模型生成），以备署名与合规质询。

### 2. OpenAI 推出 Agents API（公开测试）

> 来源：[OpenAI 官方](https://openai.com/index/introducing-the-agents-api) · [Vercel](https://vercel.com/changelog/build-with-openai-agents-api-on-vercel) · 重要度 9/10

- **事件背景**：OpenAI 于 9/10 以公开测试形式推出 Agents API，把驱动 Codex 的 harness 与基础设施以 API 形式开放给开发者，用于构建长时运行、具备编排与工具调用能力的云端 agent。除用量费用外不额外收费；agent 可部署在 OpenAI 托管的沙箱中，也可部署在自有基础设施上，合作方包括 Cloudflare、DigitalOcean 与 Oracle。Vercel 当日即上线了对应集成。
- **产业影响**：这与近期一连串信号一脉相承——NVIDIA 研究证明 harness 对 agent 效果的影响远超模型本身、DeepSeek 开源 Harness、Vercel 推出 harness 层。如今 OpenAI 把自家最成熟的 agent 外壳直接商品化，意味着 harness 正从「各家自研的核心能力」变成「平台可供给的基础设施」。
- **竞品对位**：对位 Anthropic 的托管 agent 方案、AWS Bedrock AgentCore，以及 DeepSeek Harness 等开源方案。差异点在于它背后是经过 Codex 大规模验证的编排能力。
- **PM 视角启示**：自建 harness 与采用平台 harness 之间的取舍变得现实：平台方案上手快、成熟度高，但要权衡数据流经、定制深度与供应商锁定。
- **机会信号**：harness 平台化之后，价值会上移到平台之上的垂直工作流、评测体系与治理层。
- **建议行动**：
  - 选一个现有 agent 流程用 Agents API 复刻，与自建方案做 A/B 对比（效果、成本、调试体验）。
  - 明确数据边界：托管沙箱与自有基础设施两种部署方式分别适用于哪些数据等级。

### 3. DeepSeek 开源 V4.1 Flash 并改峰谷计价，V4 Pro 下线

> 来源：[Hugging Face](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash) · [DeepSeek 官方公告](https://twitter.com/deepseek_ai/status/2097930608790167907) · [BenchLM](https://benchlm.ai/models/deepseek-v4-1-flash) · [OfficeChai](https://officechai.com/ai/deepseek-v4-1-flash-benchmarks-pricing/) · 重要度 8/10

- **事件背景**：DeepSeek 于 9/10 发布 V4.1 Flash，权重以 MIT 许可发布在 Hugging Face。模型骨干参数约 5520 亿，prefill 阶段每 token 激活约 80 亿、decode 阶段约 160 亿；支持原生图文输入、100 万 token 上下文、最长 38.4 万 token 输出。官方 API 改为峰谷计价：闲时缓存输入 $0.003、非缓存输入 $0.15、输出 $0.60 每百万 token；工作日 UTC 01:00–04:00 与 06:00–10:00 为高峰，价格翻倍。V4 Pro 档将于 9/14 下线，届时 deepseek-v4-pro 的 API 请求会自动路由到 V4.1 Flash 并按其价格计费。据报道，其在五项高难 agentic 基准中有四项超过 GPT-5.6 Sol 与 Claude Opus 5（如 DeepSWE v1.1 为 74.2 对 73.0），该数据为发布方与第三方口径，建议以自测为准。
- **产业影响**：继 8 月宣布上调 API 价格后，DeepSeek 以「合并档位 + 峰谷定价」重构价格体系：把 Pro 能力并入 Flash，简化产品线，同时用时段价差调节算力负载。
- **竞品对位**：对位 Gemini 3.8 Flash、GPT-5.6 Luna 等低价档；MIT 开源权重是其明显差异点，允许自托管以绕开峰谷价差。
- **PM 视角启示**：对国内团队而言，高峰时段恰好覆盖北京时间工作日 9–12 点与 14–18 点——实时类业务在工作时间的实际单价是闲时的两倍，成本测算必须按时段加权。
- **机会信号**：任务调度（把可延迟的批量任务挪到闲时）与自托管，都能直接转化为成本优势。
- **建议行动**：
  - 9/14 前对 deepseek-v4-pro 的调用做回归测试，确认自动改路由后的输出质量与行为变化。
  - 把离线/批量任务调度到北京时间 18 点之后与周末；重算工作时段调用的实际成本。

### 4. Cognition 发布 SWE-2：在 Kimi K3 上做万亿参数级强化学习

> 来源：[Cognition 官方](https://cognition.com/blog/swe-2) · [Hacker News](https://news.ycombinator.com/item?id=49645443) · [OfficeChai](https://officechai.com/ai/cognition-releases-swe-2-says-it-performs-close-to-frontier-at-70-lower-cost/) · 重要度 8/10

- **事件背景**：Cognition 于 9/10 发布其最强编码模型 SWE-2。该模型基于 Moonshot AI 的 2.8 万亿参数开源模型 Kimi K3（Kimi K3 在交到 Cognition 手中前已针对编码做过大量强化学习）；Cognition 称首次把强化学习扩展到数万亿参数规模，沿用 SWE-1.72 的训练设施与配方，并用单次训练覆盖全部推理强度档位。在 FrontierCode 1.1 Main 上得分 50.0%，对比 Fable 5.1 的 50.9%；官方称成本低约 64%（另有报道称约 70%，口径不一）。已在 Devin Desktop、CLI、Web 与 Fusion 上线。
- **产业影响**：应用层公司不再只能「调用」前沿模型——在足够强的开源底座上做大规模强化学习，就能以显著更低的成本逼近前沿。这正在改写「模型公司」与「应用公司」的分工边界，也说明开源权重模型已成为全球产业链中的通用底座。
- **竞品对位**：与 Claude Code、Codex、Cursor 等编码 agent 直接竞争；其价格优势来自自有模型，而非转售他人 API。
- **PM 视角启示**：拥有大量可验证任务数据（测试用例、工单闭环记录）的团队，「开源底座 + 场景 RL」已是一条可评估的路线；真正的门槛在训练基础设施与评测体系，而非模型本身。
- **机会信号**：开源底座的后训练服务、垂直领域的 RL 数据与评测体系，都是被这条路线带起来的需求。
- **建议行动**：
  - 评估自身场景是否积累了足以支撑 RL 的可验证任务数据。
  - 短期可先在编码场景用 SWE-2 做一次成本与质量对比。

### 5. Anthropic 发布蒸馏报告，美方三部门点名六家中国 AI 公司

> 来源：[TechCrunch](https://techcrunch.com/2026/09/10/anthropic-details-distillation-campaigns-from-alibaba-moonshot-ai-and-deepseek/) · [Nextgov](https://www.nextgov.com/artificial-intelligence/2026/09/intelligence-agencies-warn-chinas-large-scale-ai-model-distillation-efforts/415851/) · [Gizmodo](https://gizmodo.com/u-s-agencies-issue-stern-rebuke-of-china-based-ai-companies-over-alleged-distillation-2000808988) · 重要度 8/10

- **事件背景**：Anthropic 于 9/10 发布报告，称其观测到约 2 亿次与「蒸馏」（用其他模型的输出来训练自家模型）相关的交互，并将其归因于五个行动；报告称其中一个行动在 2026 年 5–7 月间产生约 1.51 亿次交互、分布在约 3500 个账户，并将其归因于为阿里通义千问系列模型制作训练素材，另有行动涉及月之暗面与 DeepSeek。此前 9/8，美国 NSA、CISA 与 FBI 发布联合网络安全公告，点名 DeepSeek、月之暗面、阿里、MiniMax、阶跃星辰与 Z.AI（智谱）六家公司，称其自 2024 年底以来系统性提取美国前沿模型的能力。
- **各方表态**：据报道，被点名企业截至报道时未回应置评请求；另有报道称，中方政府部门此前曾多次对类似指控表示反对。以上均为相关方的公开指控与表态，目前没有独立第三方的事实认定。
- **产业影响**：模型提供方与政府层面同时就「蒸馏」发声，意味着围绕模型访问的风控（账户审核、异常调用检测）以及跨境模型调用的相关政策都可能收紧。对依赖跨境模型调用、或使用相关开源模型的产品而言，政策层面的不确定性明显上升。
- **PM 视角启示**：这首先是一个供应链问题——无论最终事实如何认定，都应避免产品的关键链路只依赖某一侧的模型供给。对外提供模型 API 的团队，也需要具备识别批量注册与异常调用模式的能力。
- **机会信号**：API 反滥用与异常检测、模型调用的合规审计，是这类事件带起来的确定性需求。
- **建议行动**：
  - 列出产品中所有跨境模型调用与第三方开源模型依赖，逐项标注可替代方案。
  - 若对外提供模型 API，评估账户异常与批量调用的检测能力，并明确服务条款中的相关约定。
